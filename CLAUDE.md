# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

This is the source for `abizern.dev`, a developer blog built with [Hugo](https://gohugo.io/) and the `hugo-tufte` theme (Tufte CSS style). It is hosted on GitHub Pages and deployed via GitHub Actions.

## Content authoring model (the most important thing to understand)

All prose content is authored in a single org-mode file, **`Content.org`**, and exported to Hugo Markdown by **ox-hugo running inside Emacs**. The individual files under `content/` are *generated artifacts*, not sources.

Consequences:

- **To change a post, edit `Content.org`, not the files in `content/`.** Each post is an org subtree with `EXPORT_FILE_NAME`, `EXPORT_DATE`, and front-matter properties; org tags on the heading become Hugo `tags`.
- Regenerating from Emacs: `C-c C-e H H` exports the current subtree (`org-hugo-export-wim-to-md`); `C-c C-e H A` regenerates all subtrees (`org-hugo-export-wim-to-md :all-subtrees`). Claude cannot run these — flag when an Emacs export step is needed.
- **Do not delete the `content/` folder.** The GitHub deploy workflow runs Hugo but does *not* run ox-hugo, so only committed generated Markdown ends up on the site.
- `Content.org` defines macros at the top for Tufte parenthetical content. Use `{{{sidenote(text)}}}` and `{{{marginnote(text)}}}` (and the `speakerdeck`/`skillsmatter`/`youtube` macros in Talks) rather than raw HTML shortcodes; these expand to `{{<sidenote>}}`/`{{<marginnote>}}` shortcodes in the generated Markdown.

## Structure

- Content is organised into `Posts`, `Talks`, and `About` (top-level org headings). There are **no categories** — classification is by tag only. `tags/` is generated by Hugo.
- Theme lives in `themes/hugo-tufte` as a **git submodule** (a fork of the upstream theme). After cloning: `git submodule update --init`.
- Site config is `hugo.yaml`. `public/` is the built output and is gitignored.

## Tufte style constraints

- Only two heading levels are supported: Section (`h2`) and Subsection (`h3`). Do not nest content deeper than two levels within a post.
- Math (KaTeX) is enabled site-wide but can be toggled per-post via `:math false` in the subtree's `EXPORT_HUGO_CUSTOM_FRONT_MATTER`.

## Local development

```sh
hugo server -D    # build and serve locally including drafts, with hot reload
```

Notes from experience: KaTeX math sometimes fails to render locally in Safari — check in Chrome, or restart the server. Restarting the server also fixes sidenotes that get visually messed up during hot reload.

## Deployment

Pushing to `main` triggers `.github/workflows/hugo.yaml`, which builds with Hugo extended (`--gc --minify`) and deploys to GitHub Pages. Keep the pinned `HUGO_VERSION` in that workflow in sync with the Hugo version used locally. Deploy loop: regenerate content from `Content.org` in Emacs → commit → push.
