* abizern.dev

Developer blog built with Hugo and the hugo-tufte theme, served via Github Pages. The aim is a content-centric approach, without a lot of bells and whistles.

The site is built and deployed by a Github Actions workflow. Locally, changes only need to be made to =Content.org=; pushing to Github runs the Hugo build and deploys the result.

** Installation
The theme is included as a git submodule, so run =git submodule update --init= after cloning.

** Content
All content is authored in a single file, =Content.org=. [[https://hugo-tufte.netlify.app/posts/tufte-css/][ox-hugo]] converts this into the individual Markdown files that Hugo uses to build the site. The theme itself is based on [[https://hugo-tufte.netlify.app/posts/tufte-css/][tufte-css]].

The site is organised into a few top-level sections:

- Posts
- Talks
- Tags (generated automatically)
- About

There are no other categories --- everything else is organised with tags.

** Creating Content
Create a new subtree in the appropriate location within =Content.org=. Posts have a title and an optional subtitle, both set in the front matter.

Tufte's style only supports two heading levels: Section (h2) and Subsection (h3). Don't nest content any deeper than that within a post.

*** Parenthetical Content
The most distinctive part of the Tufte style is the use of _sidenotes_ and _marginnotes_. =Content.org= defines top-level macros for these, so they don't need to be written as raw escaped HTML.

** Previewing Locally
Since everything is generated from =Content.org=, that's the file to open in Emacs when working on content:

- =C-c C-e H H= exports only the current subtree (=org-hugo-export-wim-to-md=) --- not recommended for everyday use.
- =C-c C-e H A= regenerates the whole site (=org-hugo-export-wim-to-md :all-subtrees=).

Run =make preview= to build and serve the site locally, including drafts, with hot reload.

Note: KaTeX math rendering sometimes doesn't work locally in Safari --- check in Chrome instead, or restart the server. Restarting the server is also the fix if sidenotes get visually mangled during a hot reload.

Don't be tempted to delete the =content= folder outside of the regeneration step below. The Github build runs Hugo but not the ox-hugo export, so only whatever Markdown is already committed there makes it into the site.

** Makefile
A =Makefile= wraps the common commands:

- =make help= --- list the available commands.
- =make preview= --- run the local preview server with drafts (=hugo server -D=).
- =make build= --- delete the =public= folder and build the site with Hugo (=hugo --gc --minify=).
- =make clean= --- delete the =content= and =public= folders.

** Theme
Uses the hugo-tufte theme, included as a submodule of a fork so I'm not held hostage to the upstream repository. The Github fork links back to the original, so it can still be kept up to date.

** Deployment
- Run =make clean= to clear the =content= and =public= folders, then regenerate content from =Content.org= in Emacs with =C-c C-e H A=. Clearing first avoids stale files being left behind for posts that were renamed or removed.
- Commit the changes.
- Push to Github. There is a workflow that rebuilds and redeploys the site whenever the =main= branch is updated.
  - This uses a small amount of Github Actions processing time --- comfortably within the free allowance, but worth keeping an eye on.
